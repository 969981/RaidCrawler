## 优先级：不应该每次全堆扫描

1. **本次进程曾定位的候选指针**：记录 `mainBase + heapBase + owner + RaidPoint`，20分钟内、相同基址时重新读取两次完整 0x3E8 结构和当前对象的序列化虚表槽。通过才允许作为 **仅只读候选**展示；失败清缓存。可用时扫描量为零。
2. **真正的静态指针链**：只能在 ELF 指令与真实进程数据中确认根、偏移、对象生命周期后固化为 `main+root → ... → owner`。目前**没有已证实**可直接取得“本局准备发送”的 owner 的全局根，不能因为有 `main+0xE327FC` 序列化函数 RVA，就捏造指向 `x20` 的固定地址。
3. **首次无指针**：通过独立只读 TCP 通道快速搜索零售版完整 RaidPoint 结构；先8MiB，用户确认后才扩大，失败不猜地址、不自动写奖励。

## ELF 的真实 getter，不是静态 owner 指针

从用户 Library 原版 `Violet4.0.0.elf`（SHA256 `d17403eaa9d844db82f647fd2f1518806b10c0518d53602fc0ac1766298fdba0`）使用 `llvm-objdump` 核对：

```asm
main+0x1BAFFA4: ldrb w8, [x0]
main+0x1BAFFB0: ldr  x0, [x0,#0x8]   ; 包装对象 -> 实际内容指针
main+0x1BAFFB4: cbnz x0, ...
main+0x1BAFFC8: adrp x0, 0x4718000
main+0x1BAFFCC: add  x0, x0,#0x260 ; 仅备用清零缓冲
```

`main+0x4718260` 是 fallback，不是活动房主奖励位置；`main+0x1BAFF98` 是**函数**不是地址链根。`x0` / `x20` 是函数调用期间的动态输入寄存器。现阶段从 ELF 中**不能证明**存在一条固定根指针直接指向真实房主正在发送的消息对象。

## C# 高速只读 TCP 通道

[`FastSysbotReadChannel.cs`](../../RaidCrawler.Core/Host/FastSysbotReadChannel.cs) 直接使用现有 sys-botbase TCP 端口 **6000**，只发送 `peekAbsolute`，不会调用 `poke`、不改变 Switch 内存或安装额外的 NSO / sysmodule。

- **独立第二条 TCP 连接**，避免操作主 UI Socket 的大批量回包；受限读写互斥，每条命令有超时。
- 每次读取的响应是 `2*N` 个 ASCII 十六进制字符，后跟 LF（可容忍 CRLF）；循环 `ReadAsync` 累积完整数据，严格拒绝长度/十六进制/终止符异常。**不能把一次 TCP Read 当作完整回包。**
- 逐级在游戏原始序列化机器码区域使用 **448 / 4096 / 16384 字节**比较：同一字节区，用已有 SysBot.Base 标准 `ReadBytesAbsoluteAsync` 和独立通道读回结果做 **完整字节比对**。任一失败则禁用快读（不使用未知数据、不隐藏警告）。
- 校准后只使用当前已校验的最大块长，最多16KiB一条命令；单次调用最多256KiB，并继续按已校准上限分段。
- 无高速支持时，主诊断界面**询问用户是否回退旧慢速扫描**，不会擅自再扫15分钟；QuickBall×500 预设窗口失败后不偷偷进入慢速模式。
- 网络通信速度必须以使用者 Switch 实测为准；CI 只能测试完整回包、被拆分的 TCP 包、畸形响应和端到端编译，**不能保证某台 sys-botbase 实际接受16KiB单条读取**。

## 入口与验收

- **纯sys-botbase → ①自动查找候选（只读）**：优先复核本次进程缓存；没有缓存先校准高速 TCP；通过才扫描8MiB；额外32/64MiB由用户决定。
- **先机球×500 单行预设 → 自动定位**：同样优先缓存，其次高速只读扫描。
- 速度指标按实际总量/KiB/s/ETA记录；第一次连接会多花几秒做校准，后续大范围读取应该比448字节循环请求显著减少通信往返，需实机日志证明。

## 仍缺的核心验证

- 静态 ELF 不能认证运行时 `x20` 指针；此前回推 `RaidPoint-0x58` 只有布局关系，未得到实际 serializer 传入对象的现场证据。
- 主机正在开房但没打，可能存在多个副本，且后续还可能被覆盖。**缓存验证成功 ≠ 当前发送对象已确认。**
- 高速只读命中不自动改变现有写入门禁；任何真实发送、到帐、保存的证明仍需实机录制与参与者核对。
- 连接切换本地 LDN 时可能使Wi-Fi sys-botbase TCP失效，高速TCP无法弥补物理无线切换导致的断网。
